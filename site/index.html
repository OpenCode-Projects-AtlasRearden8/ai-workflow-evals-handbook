Here's a mistake almost everybody makes with AI tools. They try a new setup once, it does something impressive, and they quietly decide it works. Then, months and several updates later, it's quietly failing half the time and nobody noticed — because nobody ever wrote down what "working" looked like in the first place.

This handbook fixes that, with a set of habits you can run with a text editor and twenty minutes a week. No accounts, no API keys, no cloud calls. Everything runs locally; you can even do it on paper.

The whole book in one line: a score you didn't write down last week is a regression you can't spot this week. So — ten questions, one simple rubric, a short comparison ritual, and a pre-agreed bar. Write it down.

The canary idea

In old coal mines, miners brought a canary. As long as the bird seemed okay, the air was probably okay. A canary quiz is the same for your AI setup: not a scientific benchmark, and not a competition against anyone else's setup. It measures your setup against itself, over time. If the canary is fine, you're fine. If it drops off the perch, you know to get out — before a real task does.

Ten questions is the sweet spot. Fewer than ten and one lucky answer can fool you; more than ten and grading becomes a chore, and a chore you skip is a canary you don't have.

The four moves

MoveWhat you doChapter
1. Build the quizTen permanent questions that mirror how you actually use the tool — plus a red-line question, a known weak spot, one messy prompt, and one thing you don't yet trust it for.01
2. Score with a rubricEvery answer gets a 0, 1, or 2 — the same scale every time. Ten questions, so each run is out of 20.02
3. Spot regressionsRerun the quiz when anything changes (model update, prompt tweak, workflow edit). Compare scorecards; hunt the one silent-killer pattern.03
4. DecideA pre-agreed ship bar (default 16/20) plus a red-line veto: any red-line answer at 0 means don't ship, regardless of the total.04

Then chapter 05 turns the whole thing into a fifteen-minute weekly ritual that survives busy weeks.

What this isn't

  • Not medical advice — ever. I'm a nurse by training, so let me be extra clear: nothing here is healthcare guidance, and no AI setup should be treated as a clinical authority. This book is education about AI tooling, full stop.
  • Not a benchmark. Your only meaningful comparison is your setup this week vs. last week.
  • Not automation. This handbook is deliberately tool-free. If you want automation later, my separate project prompt-regression-cli automates the comparison step — but learn the habit first; the habit is what makes the tool worth having. (And my when-ai-gets-it-wrong-guide collects the failure stories; this is the craft that prevents them.)

What you need

  • The AI setup you already use (chatbot, local model, coding assistant — anything).
  • A place to keep notes: a plain text or Markdown file, or a paper notebook.
  • 20–30 minutes for the first round, then 15–20 minutes a week.
